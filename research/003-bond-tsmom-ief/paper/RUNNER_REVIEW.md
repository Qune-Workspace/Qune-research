## Findings

**Must-fix**

- **M1. A stop trigger blocks every later month-end run.** :283 sets `last_signal_date: record.signal_date`; for a stop record that is `stop_pending.date` (:311), for which no `decisions/<date>.json` exists; :142 then refuses for ever. Scenario: IEF stop fires 2026-11-10, switch to BIL 2026-11-11, December signal refused "previous session's decision record 2026-11-10 is missing". Tested (inline 1). Fix: `last_signal_date: record.kind === 'stop' ? state.last_signal_date : record.signal_date`, and add the December run to the stop test.
- **M2. No write-ahead state and no reconciliation with the account: a rerun can double the sleeve.** State is written only after the fill poll (:281) and the execution record only in `finish` (:170). If the process dies between `placeOrder` :265 and :281 (network timeout, OOM, operator Ctrl-C), or `state.json` is lost, the next run inside the window finds no execution record, `state.qty` 0, sizes a fresh 2 250 USD buy, and the real engine approves it (inline 3: position 4 370 USD < 5 000, concentration 4.37% < 5%, duplicate window only 60 s). The same gap after the sell fill (:208-227) leaves state saying "holding IEF 23" while the account is in cash and the journal already has the exit; the rerun's sell is refused ("short selling is not allowed") with no retry path. `pending_sell` :213 and `pending_buy` :285 are written but never read. Fix (smallest): at the gates, read live positions for IEF and BIL and refuse if they differ from `state.holding`/`state.qty`, or if `pending_sell`/`pending_buy` is set; `writeState` with `pending_*` immediately before each `placeOrder` and with the new holding immediately after the sell fill (before the buy leg). Unit test: deps whose `placeOrder` throws after recording, then a second `runMonthly`.
- **M3. An engine-blocked retry is sized on 2 250 USD, not on the proceeds.** :189 and :233 use `state.sleeve_start_usd` whenever `selling` is false; after "engine-blocked, sleeve in USD" the sleeve's cash is `engine_blocked.proceeds_usd` (:242). Scenario: proceeds 2 100 USD, IEF 95.02 → 23 shares (2 185.46 USD), 85 USD of other strategies' cash spent (inline 2). The existing test passes only because 2 195.76 and 2 250 both floor to 23. Fix: `const budget = selling ? expectedProceeds : (state.engine_blocked?.proceeds_usd ?? state.sleeve_start_usd)` at both sites; test with proceeds 2 100.

**Should-fix**

- **S1. Uninvested sleeve cash is not tracked** (:150 `sleeveEquity = qty × bid`). After the first buy 64.54 USD and after dry-run D a further 79.58 USD sit in cash but count as loss, so the 450 USD halt fires at a real loss of about 305 USD after one switch, and every record understates sleeve equity. Fix: keep `sleeve_cash_usd` in state (sleeve start minus notional, plus proceeds minus notional); equity = qty × bid + cash.
- **S2. `no_stop_holding` reports the live holding** (:304). After a stop switch the field reads BIL, contradicting the note on the same line and §11.4. Fix: set `state.no_stop_holding = target` only for `kind === 'signal'` executions (:281) and report that field in `stopCheck`.
- **S3. The 0.5% review on the sell leg does not hold the buy of the same session** (:217 sets the flag; :284 applies it only to the next session). RISK_CLEARANCE §11.4 row says "next order held for review"; the buy is the next order. Either hold the buy (then this is the engine-blocked path with a new reason) or write in the spec that a switch is one atomic rebalance and the hold applies to the following month. Decide and record; the code currently does the second without saying so.
- **S4. Re-check records have no file name the runner can find.** decide.py refuses to overwrite `<signal_date>.json` (decide.py:107), so a day-one "signal unavailable" record cannot be superseded; `run-monthly`:48 reads only `^\d{4}-\d{2}-\d{2}\.json$`. The §11.2 re-check (schedule "designed, not built") would write a correction as a new file, which the runner ignores. Fix: agree the contract now, e.g. decide.py `--suffix recheckN` and the runner taking the last `status: ok` file for the signal date.
- **S5. Unconfirmed orders are never resolved.** Market orders are `gtc` (:201, :206, :265) with a 12 s poll (6 × 2 s, :29); a sell that fills after the poll leaves `sell-unconfirmed` and the sleeve in cash with no retry path, and the buy's `pending_buy` is never consumed. Fix: `ioc` for the market orders (allowed by risk.json `time_in_force`; fill-or-cancel inside regular hours), and treat `pending_*` at the gates (M2).

**Notes**

- N1. `signal_bar_time` is stamped `<signal_date>T04:00:00Z` (:76); Alpaca stamps daily bars 05:00Z in EST months. Irrelevant until condition 3 changes the engine; then use the bar's own `t`.
- N2. §11.2 says 15:45–15:55 ET; the runner and condition 5 say 15:30–16:00. Record which governs.
- N3. Exit codes match the header (`run-monthly`:9): 0 for hold/switch/initial-buy/check-ok, 3 for every refusal and unconfirmed order, 2 for a thrown error (:83-85). Observed in dry run A (3), B (0), C (3), D (0). A throw from `placeOrder` or the fill poll mid-switch exits 2 with no state and no record written (feeds M2). The `exit: (out.exit_code = 3)` pattern also writes a stray `exit: 3` field into execution records.
- N4. Idempotence: a second run on the same day is refused by :140 once an execution record exists; while `engine_blocked` is set, :137-140 allow an immediate same-day retry, so a misfiring scheduler can consume all three retries in minutes. Require `et.ymd` later than the blocked run's date.
- N5. `max_hold_minutes` 45 days (:28): a hold decision writes no new journal entry, so an IEF position kept two months makes the journal's `within_time_limit` false at exit. Cosmetic.
- N6. decide.py's `--holding` is typed by the operator, not read from state; a wrong value is refused at :135 (fail closed). Good; the schedule should pass `state.holding`.
- N7. Time zones: `etClock` uses `Intl` with `America/New_York`, handles the "24" hour, tested for EDT (2026-10-30) and EST (2026-11-02). No finding.
- N8. decide.py record versus runner: field names and values match (`status` "ok" / "signal unavailable", `execution_date` the first NYSE day strictly after the signal date from calendar.py:162-168, `holding_before`, `target`, `mom`, `switch`; no `kind` → "signal"). Only S4 is a mismatch.
- N9. The desk journal entry carries no "paper record of a not-supported rule" text (condition 9 names `paper-log/` and the summary, so this is outside its letter); the `exit_plan.description` could carry it at no cost.
