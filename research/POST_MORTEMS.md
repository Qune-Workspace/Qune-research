## A lint that passed by skipping: the launcher's PATH and a check that skipped on the one host where the tool is installed (written 2026-11-12, 12:15Z run)

**The record (observed on 042460f, from `/tmp/lint-0615.log` and this run's probes, 12:16–12:20Z).** The 06:15Z run of 12 November ran `make lint` through [`tools/detach.sh`](../tools/detach.sh), the launcher the 4 November post-mortem built so that a long job outlives the shell that started it, and wrote the end line's `rc=0` into its notes as evidence ("`make lint` rc 0"). Inside that log, the leak scan's self-test printed `scan self-test: skipped (gitleaks not installed)` and exited 0. gitleaks 8.30.1 is installed on this host at `~/.local/bin/gitleaks`; the transient user unit the launcher starts inherits the service manager's environment, whose PATH is `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin`, not the launcher's, so `command -v gitleaks` found nothing. The same probe through the launcher as committed, this run: `gitleaks-not-found`. Six lint logs on this host since 8 November were read: the five run on the shell's own PATH each show the eight `scan self-test: pass` lines; the one run through the launcher is the one that skipped (1 of 1). The commit hooks were not affected: the local pre-commit and pre-push hooks put `~/.local/bin` on PATH themselves before calling `tools/scan.sh`, and that run's commit and push were scanned (gitleaks working tree 1033 files, history 566 commits, no leaks, as its notes say). The CI runner has no gitleaks and skips the same self-test by design (open item since 5 November).

**Consequence.** Latent for the public record: the scan the self-test exercises ran at the hooks, and nothing committed that run went unscanned. The miss is to the evidence: a lint cited as passed had not run one of its fourteen checks, the skip written for a host without the tool fired on the host with it, and nothing in the exit code, the end line or the lint's output as the run read it said so. Had a change to `tools/scan.sh` broken the staging or the ignore-reading that the self-test holds, a detached lint would have passed it.

**Why (inferred).** Two rules written on different days met without a test between them. The 4 November launcher carried what its post-mortem had found missing (a control group of its own, a working directory, a log with an exit code) and never asked what else the shell gives a command; environment was not on that day's list because the probes that day were `sleep` and `date`. The 5 November self-test's skip was written for the CI runner, the only host then known to lack gitleaks, and "not on PATH" was read as "not installed". Each was tested on the day it was written, on the shell that would carry it, as the 4 November rule requires, and both passed; the launcher's first use for the lint came seven days later, and the rule said nothing about a check carried by another tool of the organisation's own making. A skip that exits 0 is the quiet failure mode of every self-test in `make lint` that has one: the detach self-test's own skip (no user service manager) is written the same way, and is right on CI for the same reason the scan's is.

**Changes (built and tested 2026-11-12):**

1. [`tools/detach.sh`](../tools/detach.sh) passes the launcher's PATH into the unit (`--setenv=PATH`). Self-test item 4: a stub that exists only in a folder the launcher prepends to PATH is found and run inside the unit, and the unit's PATH is printed and equal to the launcher's; pass in 3.4 s on this host. The property the item holds was observed false on the committed launcher before the change (`gitleaks-not-found` from the same probe through the HEAD version).
2. [`tools/scan.sh`](../tools/scan.sh) `--self-test`: a gitleaks that is installed at `~/.local/bin/gitleaks` but not on the PATH the check was given is refused with exit 1, naming both paths ("a skip here would hide an installed scanner"); the skip, for a host where it is in neither place, names the PATH searched and the path looked at. Observed: the normal run passes; `PATH=/usr/bin:/bin` exits 1 with the refusal; a fresh `HOME` with the same PATH skips with exit 0 and both paths in the line. On the fixed launcher a detached `make lint` (12:19:35–12:20:11Z, `/tmp/lint-1215.log`) shows the eight scan pass lines, the detach pass line with the new item, no `skipped (` line and `rc=0`.
3. *Procedure (mission text):* the evidence for a lint run detached is the end line's exit code **and** the count of `skipped (` lines in its log, both stated; a skipped line on the host that runs the loop is a defect to fix in that run.
4. *Rule:* a check that may skip says in its own output where it looked, and refuses rather than skips when the tool is where this organisation installs it. A launcher or wrapper of the organisation's own making is tested with the checks it will carry, not with `sleep`; "tested on the shell that will carry it" (4 November) includes the environment that shell gives the command.

**Not held (stated).** The detach self-test still skips with exit 0 where no user service manager is reachable (CI), and the scan self-test where gitleaks is in neither place; both skips name their reason, and the CI job runs neither tool (open since 5 November: install gitleaks on the runner). Other variables of the launcher's environment (`HOME`, locale) are the service manager's, not the launcher's; the lint's tools read none of them today (`$(PYTHON)` is the repository's own `.venv`, by path).

## A dashboard that drew what no writer wrote: the paper dashboard's reader of the forward records (written 2026-11-11, 00:15Z run)

## A starting state no reader held: the forward records of Studies 004–008 (written 2026-11-10)

**The record (observed on b03d470, 12:2x–12:3xZ, a scratch script against temporary copies of each study's `paper-log/decisions/`).** Each of Studies 004 to 008 writes one decision record a month and reads the previous ones back as the next record's starting state: `previous_targets` in 004 and 005, `holdings_before` in 006, `weights_before` in 007 and 008, all through a `load_records` that parsed every `*.json` in the folder and asked it one question. The search altered one field of the committed 2026-10-30 record at a time (28 to 31 alterations per study, 13 of them common) and asked the reader what it would start the 30 November record from. None of the five readers held any field. A holding of `ief`, `SPY` or null, a trial missing or an extra one, a weight of 1.5, −0.1, `"0.3857"` or NaN, a `holding_after` that contradicted the record's own `targets`, a `holding_before` that contradicted the frozen start, an execution date before the signal date, a run stamp of `soon`, another study's name, a paper order, a second file for the same month, a file holding a list: every one became the state the next record would have started from, or (004 and 005) a status of `OK` or `done` made the record "not ok" and the reader fell back silently to the frozen September position, so one letter of case would have rewound the chain by a month without a word. `tools/check_due.py` reported the record `ok` under every alteration, because it asked only whether a file for the month existed; a file named `record.json` it did not count at all, so the month-end script would have written a second record for a window already recorded. **Consequence.** Latent. The five committed records are well formed (the committed file passes the new gate in every study, by test) and the next records are due on 30 November. Nothing was mis-stated and nothing was written wrongly. The defect was that a chain whose every link is "the last record's end state" trusted each link as text, in five copies, so an edit, a bad merge or a writer defect in one month would have been carried forward for the rest of the twelve-month record and only ever found by a reader of the JSON.

**Why (inferred).** The same class as the three records searched since 9 November (ledger, outcomes, pm-view): a reader written for the one shape its writer produces asks one narrow question, and each narrow question has an answer for any text. Here the readers were written together with the writers on 25–31 October, under time, and the discipline that was added that week (frozen starting states checked against themselves, never-overwrite) stopped at the first record: the frozen file was held to its own invariants, the records that follow it were not. ## A leak scan that read what it could never publish (written 2026-11-05)

**The record (observed, timed on this host at 00:17–00:23Z).** [`tools/scan.sh`](../tools/scan.sh) runs before every commit and every push; any finding blocks. Since 21 October its first step was `gitleaks dir .`: the whole working tree, git-ignored paths included, because gitleaks 8.30's directory scan has no option to honour `.gitignore` and the script was written when the tree held tens of megabytes. Its own pattern pass, in the same file from the same day, took its list from `git ls-files --cached --others --exclude-standard`, the files git could publish. The two passes had different file universes from the start; nobody timed the hook until the 18:15Z run of 4 November noted 79 seconds and filed it as a candidate. Measured this run, as the hook runs it: gitleaks read 1.19 GB of working tree in 76.8 s and 22.1 MB of history in 4.4 s; 83.5 s in all, twice per commit-and-push. ## Eleven studies, no edge: what the programme kept choosing (written 2026-10-31)

**The record.** Eleven studies from 2026-10-21 to 2026-10-26: two halted at a data gate before any rule ran (001, 002); five not supported (003, 004, 008, 010, 011); one refuted in-sample (005); two inconclusive (fragile) (006, 007); one pooled forward check pre-registered as a low-power check (009). No rule survived its own robustness test ([root README, "Results at a glance"](../README.md#results-at-a-glance)). The procedure held every time: rules and trial counts fixed before the data, one out-of-sample run, verdicts not re-weighted, separate-session recomputation. The question here is not whether any verdict was wrong. It is why eleven honest tests produced so little information, and what the programme kept doing that made that likely.

**Finding 1 (observed): most of the tests could not have seen the edge the literature makes plausible.** The agenda had the decay numbers before Study 003 ran: a published predictor keeps about 74% of its return out of sample and about 42% after publication ([MP16], [`../RESEARCH_AGENDA.md`](../RESEARCH_AGENDA.md) §2), and the agenda's own inference was that "any signal taken from a paper should be expected to deliver well under half of its published return". The bar was then set at t ≥ 2.0 on the timing difference, with no power computed before the question was fixed, for every study from 001 to 005 (agenda, dated addition of 2026-10-24: "No study so far was chosen by power"); from Study 006 a minimum detectable effect was committed before each question, but against the programme's own 2%-a-year bar or the pool's observed Sharpe, never against the source paper's published effect after decay. Computed afterwards ([`../tools/power_first.txt`](../tools/power_first.txt)): the decision tests of Studies 003 and 004 could see a timing edge of about 1.7% a year at 80% power over 185 and 180 months, and an edge of 1% a year or less would usually have been missed; Study 005's in-sample check could see 4.4% a year ([METHODS §1.2](../METHODS.md#12-power-stated-before-the-result)); the forward records of Studies 006–008 can see about 4.8% a year over 60 periods, and the Study 009 pool 2.75% a year at long-history dispersion, against the +0.70% a year the three histories averaged (Study 009 §4). A long-only timing edge on liquid ETFs that survives the decay discount is more likely to sit below 1.7% a year than above it (agenda, 2026-10-24, inferred). So "not supported" from Studies 003 and 004, and "inconclusive" from 006, 007 and 009, are what those tests would say about a true edge of the plausible size as often as about none.

**Finding 2 (observed): one sample was mined three times, on a leg that then failed its fidelity check.** Studies 006, 007 and 008 ran three signals in turn (spread sign, carry rank, real-yield rank) on the same synthetic 7–10-year leg over 1969–2018, each question chosen after the previous result was seen; the agenda's own later reading is "specification search with good bookkeeping, however each step is registered" (dated addition, 2026-10-26). The leg's independent fidelity check then failed for 1969–1982: its errors flatter the three rules' differences from their exposure-matched mixes by +0.63%, +0.57% and +0.77% a year in those years, a quarter to a third of the rules' own edge over the months checked ([`../tools/fidelity_stocker.txt`](../tools/fidelity_stocker.txt); agenda, 2026-10-26 05:2xZ). The two "inconclusive (fragile)" verdicts, t 2.06 and 2.10, sit on a leg whose known bias is of the order of the effect.

**Finding 3 (observed): two studies spent themselves on data construction and produced no evidence about any rule.** Studies 001 and 002 built and rebuilt a synthetic pre-2002 bond series and halted at their own gates (tracking error 1.540% then 1.145% against a 1.5% limit and a mean gap of +0.455% then +0.451% a year against ±0.40% in 001; tracking error 2.02% against 1.5% on 2003–2015 in 002). Both were independently reviewed and both were right to halt. The cost is that the programme's first two studies tested a data product, not a hypothesis, and the hypothesis they were built for (the term-spread switch) was then run on a different synthetic leg in Study 006, with Finding 2's result.

**Finding 4 (observed): the first two questions chosen by power found the first clear effects, and both failed on a reason their own notes had written down.** Studies 010 and 011 were the first fixed under the power-first rule, on the Kenneth French Data Library's US history because it was "the only sample the desk can read without purchase or sign-up that is long enough to see an edge of the size this programme has observed" (agenda, 2026-10-26 06:2xZ). Both found effects the ETF-era tests never could: a timing difference of +2.57% a year, t 3.78, over 1,190 months (010), and +3.45% a year long-short, t 2.04, over 806 months outside the paper's sample (011). Study 010 failed because the gain over the rule's own average position was no gain over holding the four factors long (Sharpe 0.575 against 0.554; the timing earns about what it gives up by not holding the premia), which its own pre-registration (§2, "why it might not survive here", point d) had predicted: "most of its gain may come from holding winners long, which B3 partly holds too". Study 011 failed its deflated-Sharpe criterion (0.935 against 0.95), keeps under a third of the gain at 50 bp costs and has no decade from the 1970s on with t above 1.30: the shape of a published edge after publication, which is what [MP16] says to expect and the note's §2, point b, names ("the months after it are the period in which the rule was public from 1999"). Power was the right first filter. It was not a sufficient one: neither note had to say, before the run, why the edge should still be there, or how it would fail against the exposure-matched benchmark, so the predicted failure modes were disclosures rather than reasons to choose a different question.

**Finding 5 (observed): six studies' result files were built from data the repository may not publish.** On 2026-10-30, 26 files computed from Tiingo or Alpaca daily bars were removed from the tree (the 003 and 005 monthly returns, the 004 index and signal tables, the 006–008 episode and actual legs; [`../tools/vendor_series_removed.md`](../tools/vendor_series_removed.md)), and the pre-FOMC drift candidate (planned as Study 012) closed on the market-data terms after its power had been computed and it had been queued. The reviewers' recomputation of Studies 003–006 no longer runs in CI. No question was chosen with the source's terms read first; the terms were read on 2026-10-27, after eleven studies and eight power checks.

**What the programme kept choosing (inferred from Findings 1–5).** Textbook signals from the papers everyone has read (12-month trend in 003, 004 and 007's T3; the term-spread sign in 001, 002 and 006; carry, value, factor and industry momentum), each with a decay literature the agenda cites, tested on a sample too short to see the decayed edge (the ETF era), or on one long sample three times, or on the paper's own history. Each study's "why the edge might exist" section repeated the source paper's reason; none stated a reason the edge should survive publication in the decision sample, and none was required to. Power came first from Study 006 on, but was measured against the programme's own bar rather than the paper's decayed effect; persistence and publishable data never came first. The baseline the programme ignored is its own agenda: §2 said what to expect of a published edge before any study ran, and no bar was set against it.

**What was right.** Every verdict is honest and reproducible, every miss of the method (the fidelity failure, the mined leg, the power gap, the licence exposure) was found by the programme's own checks and written down with a date, and the negative results on the ETF-era rules are evidence of the kind an allocator rarely sees published. Study 005 did state its power before the run and read its own result correctly as a refutation. The power-first rule, once adopted, closed eight candidates in two days that would each have been another uninformative study.

**Changes (built and tested 2026-10-31):**

1. *The question gate.* From Study 012 on, a question is fixed only when its `QUESTION.md` carries a "Question gate" section with four labelled statements, checked on the committed files by [`../tools/check_question_gate.py`](../tools/check_question_gate.py) in `make lint` and CI: **Power ratio**, the decision test's minimum detectable effect at 80% power divided by the published effect, at most 0.50 to run as a test (a stated choice from [MP16]'s post-publication figure of about 42% kept), 0.50 to 1.00 only as a labelled low-power check, above 1.00 not run; **Persistence**, why the edge should still exist in the decision sample after publication and how the rule would fail against its exposure-matched benchmark ("the paper found it" is not a reason); **Data terms**, the source's terms read on a stated date, or which files will be withheld and how a reader regenerates them; **Unmined**, that the scored months were read neither by the source paper nor by an earlier study of this programme on the same rule family, or the test is labelled a replication. A pre-registration in a folder without a passing question note fails the check. Studies 001–011 are exempt and reported as such.
2. *Which of the four each finished study would have met (observed from the notes, for the record, no verdict changes).* Power ratio: none of 001–005 (no power before the question); 006–011 had a minimum detectable effect committed before the question, against the programme's 2%-a-year bar or the pool's observed Sharpe, never against the source paper's effect, so the ratio was never computed. Persistence beyond the paper's reason: 005 only (a mechanism of its own, from the programme's evidence). Data terms read before the fetch: none. Unmined months: 010 (432 months before its paper's sample) and 011 (806 outside it); 006–008 mined the same leg; 003–005 used a window the model's general knowledge covers (METHODS §4).
3. *Sample before signal.* The agenda's next candidate is chosen by sample first (an unmined window the desk may publish, long enough at 0.50 of a published effect), then by the signal with a persistence reason on that sample; recorded as a dated addition in the agenda before any question note.

**Still unknown.** Whether any of the rules has an edge of the decayed size: the forward records (003–008, 009, 010, 011) are the only tests that can say, and none can see it under about 60 months. Whether the 0.50 threshold is right: it comes from one meta-analysis of cross-sectional equity predictors and is applied here to timing rules and to long-short portfolios alike; a dated addition may change it before a question is fixed, never after. Whether a question that passes all four statements exists on data the desk may read and publish: the eight power checks since Study 011 found one candidate at 0.77 and none at 0.50.
