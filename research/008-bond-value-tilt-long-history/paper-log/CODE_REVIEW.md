## Report (condensed quotation)

> No must-fix defect in the rule, the timing or the holds; one must-fix is a §11.2 field the record does not write (the CPI values). The 13 tests pass.
>
> **Must-fix.** (1) The record does not contain the CPI values it used. §11.2 asks for "the CPIAUCNSA and CPILFENS rows fetched that month". The record writes k, k−12, their status, π and r, but not CPI(k) or CPI(k−12) themselves. `paper-log/raw/` is git-ignored, so the hash points to a file nobody can see, and π cannot be checked from the published record. Fix: in `cpi_reading`, add `cpi_k` and `cpi_k_minus_12`. (2) History verdict in the label: already fixed in 98f1604 ('inconclusive (fragile)' → 'not supported', with a test that reads `results/history/summary.json`). I had not found this one myself.
>
> **Should-fix.** (1) "Fetched on t" is not recorded or enforced. If the run slips to t+1..t+3 and BLS releases CPI(m−1) late, inside that window, the file can contain an index published after t. Copy each CPI file's `downloaded_at_utc` from `paper-log/manifest.json` into the record, and add a note when it is later than t. (2) "The rank" (§11.2) is only written as w rounded to four decimals; also write the unrounded value. (3) Months with no ok record keep only their r; their k, k−12 and status from the current fetch are not written. (4) The starting weight is not drifted when the first ok record is a hold (inherited from Study 007): 2026-10 'signal unavailable' followed by a 2026-11 hold gives a first shadow line with `w_T1 = 0.5241` and traded 0, so no hold trades, but two months of drift are missing. Either state this in §16 (f) or drift the weight from the bars. (5) `decide --fetch --dry-run` skips the fetch and then reads `paper-log/raw/`; on a fresh checkout that is a FileNotFoundError. (6) §6.1 says the signal date needs DGS10, DGS7 and DTB3, but `calendar.signal_dates` uses only DGS10 and DTB3. This matches the history and the episode, so the code should stay; the wording should be noted.
>
> **Checked and correct.** Starting weights: the episode path gives 686 defined real yields per series (2025-11 undefined), r at 2026-09 matches to full precision, and the weights come out exactly 0.5241, 0.654 and 0.9916 (test, not skipped). CPI reading: k is never m; CPI(m−1) not yet in the file (including an empty row at the end) gives the availability rule; an empty row before the last value means never published, r undefined, the trial holds, as §16 (b) says; the October 2025 gap at k−12 makes 2026-11 hold. Realistic runs on the frozen files extended in memory through records for 2026-10 to 2027-02: 2026-10 ok (n = 687) [weights omitted by the author, see above]; 2026-11 holds all three trials with the right notes; 2026-12 trades with n = 688 and 2026-11 left out; a constructed never-published 2026-12 index makes 2027-01 hold; records survive a JSON round trip; no crash. Earlier forward months: an earlier ok record's r is reused, including an extreme value; a 'signal unavailable' or missing month is recomputed from the current fetch at its own signal date and the record says so; a null r is left out and n counts defined values only. Ranks: the expanding rank (minimum 60) and the trailing 120 (denominator 119) over defined values only. No look-ahead: FRED is cut at t, a later CPI row does not change the weights. Holds: a null target passes through the hold engine with traded fraction 0 and the drifted weight. Shadow line: four-decimal weights; B3 at the frozen w̄; d = T1 − B3^T1. Clock and scoring: wait / ok / unavailable, the scoring date in record 61, "Not yet scored", `paper_order` false, the input hashes and the UTC time as specified.
