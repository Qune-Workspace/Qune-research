## Report (condensed quotation)

> FAIL: one must-fix has to land before the 2026-10-30 run. The rest of the module meets the spec.
>

Three scratch scripts on constructed data only: `exp.py` (9 experiments); `cli.py` (11 runs of `main()` with the paper-log dirs, the clock, `load_inputs`, `load_series` and `fetch_inputs` replaced by fakes; the frozen files were synthetic too, so no weight came from real data); `mut.py` (a missing-bar check and one mutation run). No network, no fetch, no real `decide` or `shadow`; `git status` clean afterwards.
>
> Checks: (1) look-ahead PASS (the test does not prove the cut, 3a); (2) rank history PASS (687 frozen carries plus one per forward month; n = count; §6.2 formula exact), except finding 2; (3) trend PASS (13 dates; the 12-row lag confirmed with a constructed path; a missing bar on t−12 reads the previous close), not proven by the test (3b); (4) finality, wait and unavailable FAIL on finding 1, otherwise correct; (5) `run_with_holds` PASS, exactly equal to `tilt.run_tilt`, None at i = 0 and consecutive Nones trade 0.0 and drift correctly; (6) `shadow_line` PASS; (7) `interim`, `score`, `forward_verdict` PASS against §11.4, see finding 2 and note 5; (8) CLI `main()` PASS (refusals exit 1 and write nothing; `--dry-run` writes and fetches nothing; writes only to `decisions/`, `waits.csv`, `shadow.csv`, `interim.json`); (9) tests against paper-log/README.md partly proven, finding 3.
>
> 1. **must-fix**, `signal_status`: no check that each FRED series has a row on t itself. When t is the month's last weekday, as 2026-10-30 is, the list of later days is empty, so no FRED check runs. Scenario: DGS10 and DTB3 have their 2026-10-30 row, DGS7 not yet (FRED updates series separately) → "final", T1/T1a/T1b/T2 = None, T3 = 1.0, a record written and never rewritten. Fix: require a row on t in every series before the later-days loop; an empty row on t still gives the §16 (e) hold; add a test.
> 2. **should-fix**: if DGS7 is empty on one forward signal date, every later month holds T1/T1a/T1b/T2 for the rest of the record, which §16 (e) does not allow (it allows a hold only when the weight is undefined on t). Knock-on: held weights drift, so sd(w_T1) > 0 and `forward_verdict` scores a block in which the rule never acted (60 held periods: "inconclusive (forward)" instead of "not testable"). Fix: hold only if the current month's carry is undefined; rank on the defined carries; in `score`, take sd(w_T1) from the records' non-null targets, not the drifted shadow weights.
> 3. **should-fix (tests)**: (a) the look-ahead test still passes with the cut removed; (b) a constant drift cannot tell the 12-row lag or the "last bar on or before" read; (c) `np.allclose(..., atol=0)` keeps rtol 1e-5, so 1e-9 errors pass; (d) the shadow test's expected returns come from `run_with_holds` itself (circular), B1 and B2 are not checked, the `append_shadow` "does not follow" guard is untested; (e) `main()` has no test.
> 4. **should-fix**: `input_sha256` hashes only the fetched files; the frozen FRED files that supply 687 of the rank's carries and `results/episode/summary.json` (the starting weights) are not hashed.
> 5. **note**: `periods_to_scoring` is 60, not 0, at n = 60 (inherited from Study 006). Fix: `(-n) % BLOCK_PERIODS`.
> 6. **note**: `main()` relies on default arguments bound at definition time; a test that monkeypatches the paths would still write the real `paper-log/`. Fix: pass the paths explicitly.
> 7. **note**: the carries of earlier forward months are recomputed from each new fetch, not read from their records; a FRED revision would silently change n and the rank. Fix: compare with the earlier record's carry and note a mismatch, or read it from the record.
> 8. **note**: `forward_verdict` does not report the detectable effect size for "inconclusive" (Study 006 §11.4: "the note records" it); a write-up item.
